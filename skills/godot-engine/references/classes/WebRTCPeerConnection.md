# WebRTCPeerConnection

**Inherits:** RefCounted

Interface to a WebRTC peer connection.

A WebRTC connection between the local computer and a remote peer. Provides an interface to connect, maintain, and monitor the connection. Setting up a WebRTC connection between two peers may not seem a trivial task, but it can be broken down into 3 main steps: - The peer that wants to initiate the connection (`A` from now on) creates an offer and sends it to the other peer (`B` from now on). - `B` receives the offer, generates an answer, and sends it to `A`. - `A` and `B` then generate and exchange ICE candidates with each other. After these steps, the connection should be established.

## Methods

- `add_ice_candidate(media: String, index: int, name: String) -> int[Error]` — Add an ice candidate generated by a remote peer (and received over the signaling server).
- `close() -> void` — Close the peer connection and all data channels associated with it.
- `create_data_channel(label: String, options: Dictionary = {}) -> WebRTCDataChannel` — Returns a new WebRTCDataChannel (or `null` on failure) with given `label` and optionally configured via the `options` dictionary.
- `create_offer() -> int[Error]` — Creates a new SDP offer to start a WebRTC connection with a remote peer.
- `get_connection_state() -> int[WebRTCPeerConnection.ConnectionState]` *const* — Returns the connection state.
- `get_gathering_state() -> int[WebRTCPeerConnection.GatheringState]` *const* — Returns the ICE `GatheringState` of the connection.
- `get_signaling_state() -> int[WebRTCPeerConnection.SignalingState]` *const* — Returns the signaling state on the local end of the connection while connecting or reconnecting to another peer.
- `initialize(configuration: Dictionary = {}) -> int[Error]` — Re-initialize this peer connection, closing any previously active connection, and going back to state `STATE_NEW`.
- `poll() -> int[Error]` — Call this method frequently (e.g. in `Node._process` or `Node._physics_process`) to properly receive signals.
- `set_default_extension(extension_class: StringName) -> void` *static* — Sets the `extension_class` as the default WebRTCPeerConnectionExtension returned when creating a new WebRTCPeerConnection.
- `set_local_description(type: String, sdp: String) -> int[Error]` — Sets the SDP description of the local peer.
- `set_remote_description(type: String, sdp: String) -> int[Error]` — Sets the SDP description of the remote peer.

## Signals

- `data_channel_received(channel: WebRTCDataChannel)` — Emitted when a new in-band channel is received, i.e. when the channel was created with `negotiated: false` (default).
- `ice_candidate_created(media: String, index: int, name: String)` — Emitted when a new ICE candidate has been created.
- `session_description_created(type: String, sdp: String)` — Emitted after a successful call to `create_offer` or `set_remote_description` (when it generates an answer).

## Enum ConnectionState

- `STATE_NEW = 0` — The connection is new, data channels and an offer can be created in this state.
- `STATE_CONNECTING = 1` — The peer is connecting, ICE is in progress, none of the transports has failed.
- `STATE_CONNECTED = 2` — The peer is connected, all ICE transports are connected.
- `STATE_DISCONNECTED = 3` — At least one ICE transport is disconnected.
- `STATE_FAILED = 4` — One or more of the ICE transports failed.
- `STATE_CLOSED = 5` — The peer connection is closed (after calling `close` for example).

## Enum GatheringState

- `GATHERING_STATE_NEW = 0` — The peer connection was just created and hasn't done any networking yet.
- `GATHERING_STATE_GATHERING = 1` — The ICE agent is in the process of gathering candidates for the connection.
- `GATHERING_STATE_COMPLETE = 2` — The ICE agent has finished gathering candidates.

## Enum SignalingState

- `SIGNALING_STATE_STABLE = 0` — There is no ongoing exchange of offer and answer underway.
- `SIGNALING_STATE_HAVE_LOCAL_OFFER = 1` — The local peer has called `set_local_description`, passing in SDP representing an offer (usually created by calling `create_offer`), and the offer has been applied successfully.
- `SIGNALING_STATE_HAVE_REMOTE_OFFER = 2` — The remote peer has created an offer and used the signaling server to deliver it to the local peer, which has set the offer as the remote description by calling `set_remote_description`.
- `SIGNALING_STATE_HAVE_LOCAL_PRANSWER = 3` — The offer sent by the remote peer has been applied and an answer has been created and applied by calling `set_local_description`.
- `SIGNALING_STATE_HAVE_REMOTE_PRANSWER = 4` — A provisional answer has been received and successfully applied in response to an offer previously sent and established by calling `set_local_description`.
- `SIGNALING_STATE_CLOSED = 5` — The WebRTCPeerConnection has been closed.
